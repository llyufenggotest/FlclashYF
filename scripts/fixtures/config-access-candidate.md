# Config-access diagnostic candidate (not a connectivity fix)

The device evidence does not establish a legal shared filesystem namespace. This candidate keeps the supported container API, signing, opaque loader, ownership and all protocol/data-plane behavior. It does not guess parent paths, copy private YAML to preferences, or claim sandbox permission repair.

## Production behavior
- After the actual Dart config write, an optional in-process method reports the location to Runner. It is retained only in Runner local defaults. No user path enters providerConfiguration or diagnostics.
- After validating the cached manager/provider owner, Runner atomically writes a <=512-byte version/revision/random-nonce marker beside that actual config. Only that nonsecret marker enters providerConfiguration; startupControlV1 retains its exact original schema. OnDemand/cold startup uses the persisted same revision. Old managers without markers continue normally. NE only reads; foreign/stale owners never trigger writes.
- Before quickSetup, NE opens config.yaml O_RDONLY|O_NONBLOCK|O_NOFOLLOW, checks regular-file metadata, reads at most one byte and closes. No diagnostic full-config load/hash remains. Large configs are not loaded by the probe. Setup diagnostic JSON parsing is capped at 1 MiB. No diagnostic changes Core admission.
- The Core wrapper retains its exported function/callback ABI. Only init JSON with config-access-version=1 opts into @CA1:stage:kind:errno. Existing callers retain historical output. Actual decode/init/setup/apply operations execute inside the tested quicksetup.Run helper; errors.As unwraps typed errno, never error-text matching. Panics return a closed code. Legacy unstructured failures become unknown, never invented stages.
- Failure classification passes through the already-device-observed NSError domain com.flclashyf.iPadDiagnostic and numeric code. Runner decodes and appends a bounded config_access event to its own export; no readable NE shared log is required. Legacy 300–303 decoding remains.

## Closed wire v1
Core stage: 0 unknown legacy,1 init decode,2 initialize false,3 setup decode,4 apply,5 panic.
Core kind: 0 no typed error,1 other error,2 typed syscall,3 panic. Canonical errno values: 0 unknown,2 ENOENT,13 EACCES,1 EPERM,20 ENOTDIR,5 EIO,24 EMFILE,23 ENFILE (Windows syscall values are mapped, not serialized verbatim).
Probe: 0 no root,1 actual open+bounded read OK,2 absent,3 denied/protection unknown,4 invalid,5 nonregular,6 fstat failure,7 read failure,8 other open failure. POSIX denial cannot distinguish iOS data protection; no false protected claim. Cocoa and underlying POSIX mapping is tested separately.
Challenge: 0 no legacy marker,1 match,2 missing/unreadable,3 mismatch/old nonce,4 invalid envelope/revision,5 nonregular/oversize. It proves only marker namespace access at observation time, not resources/RPC or connectivity.
Setup: 0 unavailable,1 empty object,2 populated object,3 invalid,4 oversized. Source:0 fallback/unavailable,1 cached setup defaults,2 shared-state snapshot,3 reserved. home_equal is actual serialized Core argument versus probe-root string equality, not Runner/NE root equality.
NSError code starts at 1,000,000 then mixed-radix packing: stage,kind(4),core_errno_index(8),probe(9),probe_errno_index(8),challenge(6),setup(5),source(4),home_equal(2). Decoder bounds reject out-of-range codes. Export contains only closed integers, never callback text, user paths, config bytes/hashes or nonce.

## Acceptance / limits
Portable contract RED was run on immutable 81e70 production before edits; candidate portable contracts and real pure-Go helper tests pass. Mac gate compiles immutable 81e70 full store/helper/RPC declarations and observes the existing unescaped-home JSON behavior with a synthetic quoted temp directory, then compiles candidate and tests actual absent/open/nonregular/large sparse files, marker mismatch/old revision/poison/legacy, errno and privacy. A second full production provider/manager/coordinator/diagnostics binary asserts original callback failure survives archived NSError and Runner-local export, cold/OnDemand revision coherence and foreign-owner no-mutation. Framework boundaries only are doubled. Neither this synthetic JSON fix nor temp-file tests establish the device root cause.

Windows cannot execute Swift/Xcode: exit 2 BLOCKED, not native PASS or semantic RED. Existing required startup job now requires this native gate plus normal/lowmem helper tests, with always-upload source/compiled hashes and commands/exits, and remains a dependency of IPA packaging. Existing baseline assertions are preserved; the envelope-only lexical check now scopes to its declaration instead of the appended independent diagnostic helper. Existing full Xcode build still runs during the normal no-codesign build before archive/package output. No push/dispatch was performed; parent must execute Mac CI and inspect artifact/device results.
